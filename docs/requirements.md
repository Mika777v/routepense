# routepense 要件定義

- 作成日: 2026-11-02
- 状態: 初版（MVP の要件）
- 前提: リポジトリ直下の `CLAUDE.md`（技術スタック・設計方針）

---

## 1. 目的

- 自分の交通費（通勤・臨時の移動）を、日ごとに記録して月ごとに合計を確認できるようにする。
- 「出勤ルートを登録しておき、期間と曜日の条件でまとめて勤務区分を設定する」ことで、毎日の入力の手間を減らす。
- 記録は自分用であり、会社への提出は行わない。
- ただし将来、会社で使う場合（複数ユーザー・精算システムへの転記・CSV出力）に作り直しが少なく済むよう、データの形を整えておく。
- TypeScript の学習教材も兼ねる（`docs/textbook/`）。

## 2. 利用者

| 項目 | 内容 |
|---|---|
| 利用者 | 開発者本人の1名のみ |
| 利用環境 | 自分のPCのブラウザ（localhost）。スマホなど他端末からの利用は想定しない |
| 認証 | なし |
| 将来への備え | すべての記録にユーザーIDを持たせる（今は固定値1つ） |

## 3. 機能一覧

### F1. ルート管理
- ルートの登録・一覧・削除ができる。
- 項目: ルート名、出発地、到着地、交通手段（電車 / バス / その他）、片道運賃。
- 運賃は手で入力する（経路検索はしない）。
- ルートを変更・削除しても、過去の日次記録の金額と区間は変わらない（→ F3・データ項目のスナップショット）。

### F2. カレンダー入力
- 月単位のカレンダーを表示し、月を切り替えられる。
- 日をクリックすると、その日の勤務区分を選べる。
  - **在宅**: 交通費 0 円
  - **出勤**: 登録済みルートから1つ選ぶ。交通費は常に往復（片道運賃 × 2）
  - **休日**: 日次記録を作らない（既存の記録があれば削除する）
- 1日に使う通常ルートは1つだけ。

### F3. 一括設定（CLAUDE.md の「一括登録」）
- カレンダー画面の中にある「一括設定」ボタンから開く。
- 入力: 期間（開始日・終了日）、曜日の条件（例: 平日のみ）、勤務区分（在宅 / 出勤＋ルート）。
- 条件に合う日へ、同じ勤務区分をまとめてカレンダー上に当てはめる。
- 当てはめた後、カレンダー上で日ごとに直してから「登録」で保存する。
- 期間内にすでに記録がある日は、登録の前に「◯日分を上書きします」と確認を出し、了承したら上書きする。
- 対象日の計算は純粋関数として作り、テストを書く（CLAUDE.md の方針どおり）。

### F4. 追加の移動
- ある日の記録に、通常ルートとは別の移動を後から足せる（1日に複数件まで）。
- 入力方法は2通り:
  - 手で入力する（出発地・到着地・交通手段・片道運賃）
  - 登録済みのルートから選ぶ（よく行く客先など）。選んだ時点の値をコピーする
- 片道 / 往復を選べる。往復の金額は片道運賃 × 2。
- 目的・メモを書ける（例: 「客先B打合せ」）。

### F5. 月ごとの表示
- カレンダー表示と表表示を、同じ画面で切り替えられる。
- 表示する項目: 日付、勤務区分、交通費（通常ルート＋追加の移動の合計）。
- 表表示では、追加の移動の内訳（区間・片道/往復・金額・目的）も確認できる。
- 月の交通費の合計を表示する。

## 4. 画面の流れ

```
[ルート管理画面] ⇄ [月次画面（カレンダー / 表 切替）]
                         │
                         ├─ 日をクリック ──▶ [日の編集パネル]
                         │                     ├─ 勤務区分の選択（在宅 / 出勤＋ルート / 休日）
                         │                     └─ [追加の移動フォーム]（手入力 or ルートから選択）
                         │
                         └─ 「一括設定」ボタン ──▶ [一括設定ダイアログ]
                                                   期間・曜日条件・勤務区分を入力
                                                   → カレンダーへ当てはめ
                                                   → 日ごとに調整
                                                   → 「登録」（上書き確認）
```

1. 最初にルート管理画面で、通勤ルート（例: 自宅↔本社）を登録する。
2. 月次画面を開き、「一括設定」で期間と「平日のみ・出勤（本社ルート）」を当てはめる。
3. 在宅の日・休みの日をカレンダー上でクリックして直し、「登録」する。
4. 臨時の移動があった日は、日の編集パネルから追加の移動を足す。
5. 表表示に切り替え、月の合計と内訳を確認する。

## 5. データの項目

型は `shared/` に置き、フロントとバックで共有する。日付は `YYYY-MM-DD` の文字列、金額は円単位の整数で扱う。

### ルート（Route）
| 項目 | 型の想定 | 説明 |
|---|---|---|
| id | string | ルートの識別子 |
| userId | string | 持ち主（今は固定値） |
| name | string | ルート名（例: 自宅↔本社） |
| from | string | 出発地 |
| to | string | 到着地 |
| transport | `"train" \| "bus" \| "other"` | 交通手段 |
| oneWayFare | number（整数・円） | 片道運賃 |

### 勤務区分（WorkStyle）— 判別可能なユニオン型
```ts
type WorkStyle =
  | { kind: "remote" }
  | { kind: "commute"; routeId: string; route: RouteSnapshot };
```
- 「休日」は勤務区分に含めない。休日は「日次記録が存在しない日」として表す。
- `RouteSnapshot` は、記録した時点のルートの値（name, from, to, transport, oneWayFare）のコピー。
- 出勤日の交通費 = `route.oneWayFare × 2`（常に往復）。

### 日次記録（DailyRecord）
| 項目 | 型の想定 | 説明 |
|---|---|---|
| id | string | 記録の識別子 |
| userId | string | 持ち主（今は固定値） |
| date | string（YYYY-MM-DD） | 日付。ユーザーごとに1日1件 |
| workStyle | WorkStyle | 勤務区分 |
| extraTrips | ExtraTrip[] | 追加の移動（0件以上） |

### 追加の移動（ExtraTrip）
| 項目 | 型の想定 | 説明 |
|---|---|---|
| id | string | 識別子 |
| from | string | 出発地 |
| to | string | 到着地 |
| transport | `"train" \| "bus" \| "other"` | 交通手段 |
| oneWayFare | number（整数・円） | 片道運賃 |
| tripType | `"oneWay" \| "roundTrip"` | 片道 / 往復 |
| purpose | string（任意） | 目的・メモ |
| sourceRouteId | string（任意） | ルートから選んだ場合の元ルート |

- 追加の移動の金額 = 片道なら `oneWayFare`、往復なら `oneWayFare × 2`。
- その日の交通費 = 勤務区分の交通費 + 追加の移動の金額の合計。
- 区間・交通手段・片道/往復・金額を必ず持たせ、将来の精算システムへの転記やCSV出力に備える。

### 一括設定の入力（BulkInput）
| 項目 | 型の想定 | 説明 |
|---|---|---|
| startDate | string（YYYY-MM-DD） | 開始日 |
| endDate | string（YYYY-MM-DD） | 終了日（開始日以降） |
| weekdays | 曜日の集合 | 対象の曜日（例: 月〜金） |
| workStyle | WorkStyle | 当てはめる勤務区分 |

### バリデーション（API の受け口で行う）
- 日付が `YYYY-MM-DD` の実在する日であること。終了日 ≥ 開始日であること。
- 運賃が 0 以上の整数であること。
- 出勤の `routeId` が登録済みのルートであること（記録を作る時点で確認する）。

## 6. スコープ外

- 承認フロー、複数ユーザー、認証（ただしユーザーIDの項目は持たせておく）
- 経路検索・運賃の自動計算（乗換案内などの外部API連携）
- CSV出力、PDF出力（出力しやすいデータの形にだけしておく）
- スマホなど他端末からの利用、外部へのデプロイ
- 会社への提出・精算システムとの連携
- 1日に複数の通常ルートを使う、通常ルートを片道だけにする（これらは「追加の移動」で表す）

## 7. 未決事項

| # | 内容 | メモ |
|---|---|---|
| U1 | 経路検索（乗換案内など）との連携 | 理想は「経路検索 → ルート選択 → 金額算出」。運賃を受け取る部分を差し替えやすくしておく。有料APIの要否を調べる |
| U2 | 祝日の扱い | 「平日のみ」に祝日を含めるか。祝日データをどこから得るか。MVPでは祝日を区別せず、カレンダー上で手で「休日」にする想定 |
| U3 | 曜日の条件の指定方法 | 「平日のみ / 毎日」のプリセットだけにするか、曜日を個別に選べるようにするか |
| U4 | 一括設定以外の、1日分の編集の保存のタイミング | クリックした時点で保存するか、一括設定と同じく「登録」ボタンでまとめて保存するか |
| U5 | 在宅日に追加の移動を付けられるか | 例: 在宅勤務だが午後だけ客先へ行った日。休日に移動があった場合の扱いも含む |
| U6 | ルートの編集機能 | CLAUDE.md の MVP は「登録・一覧・削除」。運賃改定に備えて編集を入れるか（入れても、過去の記録はスナップショットなので変わらない） |
| U7 | 削除されたルートを参照する記録の表示 | `routeId` は残し、表示はスナップショットの値を使う想定 |
| U8 | 月をまたぐ一括設定 | 期間が複数の月にまたがる場合、カレンダーの表示をどうするか |

# routepense 要件定義

- 作成日: 2026-11-02
- 更新日: 2026-11-02（未決事項 U2〜U9 を決定）
- 状態: MVP の要件（確定）
- 前提: リポジトリ直下の `CLAUDE.md`（技術スタック・設計方針）

---

## 1. 目的

- 自分の交通費（通勤・臨時の移動）を、日ごとに記録して月ごとに合計を確認できるようにする。
- 「出勤ルートを登録しておき、期間と曜日の条件でまとめて勤務区分を設定する」ことで、毎日の入力の手間を減らす。
- 記録は自分用であり、会社への提出は行わない。
- ただし将来、会社で使う場合（複数ユーザー・精算システムへの転記・CSV出力）に作り直しが少なく済むよう、データの形を整えておく。
- TypeScript の学習教材も兼ねる（`docs/textbook/`）。

## 2. 利用者

| 項目 | 内容 |
|---|---|
| 利用者 | 開発者本人の1名のみ |
| 利用環境 | 自分のPCのブラウザ（localhost）。スマホなど他端末からの利用は想定しない |
| 認証 | なし |
| 将来への備え | すべての記録にユーザーIDを持たせる（今は固定値1つ） |

## 3. 機能一覧

### F1. ルート管理
- ルートの登録・一覧・編集・削除ができる。
- 項目: ルート名、出発地、到着地、交通手段（電車 / バス / その他）、片道運賃。
- 運賃は手で入力する（運賃の自動計算はしない）。
- 経路の参照（U1）: 出発駅・到着駅を入れると、駅すぱあとの経路結果のページを開ける。そのページの URL をルートに残せる（任意。手でも直せる）。API のキーが無い環境では、この機能は出さない。
- ルートを編集すると、その後に作る記録から新しい値が使われる。
- ルートを編集・削除しても、過去の日次記録の金額と区間は変わらない（記録にその時点の値をコピーしているため。→ 5. データの項目）。

### F2. カレンダー入力
- 月単位のカレンダーを表示し、月を切り替えられる。
- 日をクリックすると、その日の勤務区分を選べる。選んだ時点ですぐ保存する。
  - **在宅**: 通常の交通費は 0 円
  - **出勤**: 登録済みルートから1つ選ぶ。交通費は常に往復（片道運賃 × 2）
  - **休日**: 通常の交通費は 0 円
- 何も選んでいない日（日次記録が無い日）は「**未入力**」と表示し、休日とは区別する。
- 1日に使う通常ルートは1つだけ。
- 日の記録を消して「未入力」に戻すこともできる。

### F3. 一括設定（CLAUDE.md の「一括登録」）
- カレンダー画面の中にある「一括設定」ボタンから開く。
- 入力:
  - 期間（開始日・終了日）: **表示している月の中だけ**で選べる
  - 曜日の条件: 月〜日を1つずつチェックで選ぶ。「平日」「毎日」のボタンで、チェックをまとめて入れられる
  - 勤務区分: 在宅 / 出勤＋ルート / 休日
  - 祝日を除く: チェック（最初から ON）。ON なら、条件に合う日のうち祝日には当てはめず、その日の記録は今のまま残す。期間の中の祝日を、チェックの横に示す
- 条件に合う日へ、同じ勤務区分をまとめてカレンダー上に当てはめる（この段階ではまだ保存しない）。
- 当てはめた後、カレンダー上で日ごとに直してから「登録」で保存する。
- 期間内にすでに記録がある日は、登録の前に「◯日分を上書きします」と確認を出し、了承したら上書きする。
  - 上書きするのは**勤務区分だけ**で、その日の追加の移動は残す。
  - 確認画面には、追加の移動がある日も示す。
- 対象日の計算と上書きの組み立ては純粋関数として作り、テストを書く（CLAUDE.md の方針どおり）。

### F4. 追加の移動
- 日の記録に、通常ルートとは別の移動を足せる（1日に複数件。在宅・出勤・休日のどの日にも付けられる）。
- 入力方法は2通り:
  - 手で入力する（出発地・到着地・交通手段・片道運賃）
  - 登録済みのルートから選ぶ（よく行く客先など）。選んだ時点の値をコピーする
- 片道 / 往復を選べる。往復の金額は片道運賃 × 2。
- 目的・メモを書ける（例: 「客先B打合せ」）。
- 編集・削除ができる。
- 「未入力」の日に追加の移動を足すときは、先に勤務区分を選ぶ。

### F5. 月ごとの表示
- カレンダー表示と表表示を、同じ画面で切り替えられる。
- 表示する項目: 日付、勤務区分（在宅 / 出勤＋ルート名 / 休日 / 未入力）、交通費（通常ルート＋追加の移動の合計）。
- 表表示では、追加の移動の内訳（区間・片道/往復・金額・目的）も確認できる。
- 月の交通費の合計を表示する。
- 祝日は、カレンダーのマスと表の日付の横に祝日名（例: 文化の日）を表示する。勤務区分は変えない（祝日の記録も、ほかの日と同じに表示する）。

### F6. 祝日の一覧
- 祝日の一覧（日付と祝日名）は、アプリの中に定数で持つ（`shared/` に置き、フロントとバックで共有する。DB には入れない）。
- 内閣府の「国民の祝日」の一覧に合わせ、振替休日・国民の休日も含める。
- 年ごとに手で一覧を直して更新する。インターネットからは取らない。最初は 2026年・2027年 を入れる。
- 一覧に無い年の日は、祝日が無いものとして扱う。

## 4. 画面の流れ

```
[ルート管理画面] ⇄ [月次画面（カレンダー / 表 切替）]
（登録・編集・削除）        │
                         ├─ 日をクリック ──▶ [日の編集パネル]（変更はすぐ保存）
                         │                     ├─ 勤務区分の選択（在宅 / 出勤＋ルート / 休日 / 未入力に戻す）
                         │                     └─ [追加の移動フォーム]（手入力 or ルートから選択）
                         │
                         └─ 「一括設定」ボタン ──▶ [一括設定ダイアログ]
                                                   期間（表示中の月の中）・曜日のチェック・勤務区分を入力
                                                   → カレンダーへ当てはめ（未保存）
                                                   → 日ごとに調整
                                                   → 「登録」（上書き確認 → 保存）
```

1. 最初にルート管理画面で、通勤ルート（例: 自宅↔本社）を登録する。
2. 月次画面を開き、「一括設定」で今月の期間と「平日・出勤（本社ルート）」を当てはめる。土日には「休日」を当てはめる。
3. 在宅の日・祝日などをカレンダー上で直し、「登録」する。
4. 臨時の移動があった日は、日の編集パネルから追加の移動を足す。
5. 表表示に切り替え、月の合計と内訳を確認する。未入力の日が残っていないかも確かめる。

## 5. データの項目

型は `shared/` に置き、フロントとバックで共有する。日付は `YYYY-MM-DD` の文字列、金額は円単位の整数で扱う。

### ルート（Route）
| 項目 | 型の想定 | 説明 |
|---|---|---|
| id | string | ルートの識別子 |
| userId | string | 持ち主（今は固定値） |
| name | string | ルート名（例: 自宅↔本社） |
| from | string | 出発地 |
| to | string | 到着地 |
| transport | `"train" \| "bus" \| "other"` | 交通手段 |
| oneWayFare | number（整数・円） | 片道運賃 |
| searchUrl | string（任意） | 経路結果のページの URL（U1）。記録にはコピーしない |

### 勤務区分（WorkStyle）— 判別可能なユニオン型
```ts
type WorkStyle =
  | { kind: "remote" }
  | { kind: "commute"; routeId: string; route: RouteSnapshot }
  | { kind: "holiday" };
```
- 「未入力」は勤務区分に含めない。日次記録が存在しない日として表す。
- `RouteSnapshot` は、記録した時点のルートの値（name, from, to, transport, oneWayFare）のコピー。
- 出勤日の通常の交通費 = `route.oneWayFare × 2`（常に往復）。在宅・休日は 0 円。
- ルートが削除されても `routeId` は残し、表示には `route`（コピー）の値を使う。削除済みであることは表示しない。

### 日次記録（DailyRecord）
| 項目 | 型の想定 | 説明 |
|---|---|---|
| id | string | 記録の識別子 |
| userId | string | 持ち主（今は固定値） |
| date | string（YYYY-MM-DD） | 日付。ユーザーごとに1日1件 |
| workStyle | WorkStyle | 勤務区分 |
| extraTrips | ExtraTrip[] | 追加の移動（0件以上） |

### 追加の移動（ExtraTrip）
| 項目 | 型の想定 | 説明 |
|---|---|---|
| id | string | 識別子 |
| from | string | 出発地 |
| to | string | 到着地 |
| transport | `"train" \| "bus" \| "other"` | 交通手段 |
| oneWayFare | number（整数・円） | 片道運賃 |
| tripType | `"oneWay" \| "roundTrip"` | 片道 / 往復 |
| purpose | string（任意） | 目的・メモ |
| sourceRouteId | string（任意） | ルートから選んだ場合の元ルート |

- 追加の移動の金額 = 片道なら `oneWayFare`、往復なら `oneWayFare × 2`。
- その日の交通費 = 勤務区分の交通費 + 追加の移動の金額の合計。
- 区間・交通手段・片道/往復・金額を必ず持たせ、将来の精算システムへの転記やCSV出力に備える。

### 一括設定の入力（BulkInput）
| 項目 | 型の想定 | 説明 |
|---|---|---|
| startDate | string（YYYY-MM-DD） | 開始日 |
| endDate | string（YYYY-MM-DD） | 終了日（開始日以降・開始日と同じ月） |
| weekdays | 曜日の集合 | 対象の曜日（月〜日から1つ以上） |
| workStyle | WorkStyle | 当てはめる勤務区分 |
| skipHolidays | boolean | 祝日を除くか（F3） |

- 一括設定で上書きするときは、既存の記録の `workStyle` だけを置き換え、`extraTrips` は残す。

### バリデーション（API の受け口で行う）
- 日付が `YYYY-MM-DD` の実在する日であること。終了日 ≥ 開始日で、同じ月であること。
- 曜日の条件が1つ以上選ばれていること。
- 一括設定の「祝日を除く」が true / false であること。
- 運賃が 0 以上の整数であること。
- 出勤の `routeId` が登録済みのルートであること（記録を作る時点で確認する）。

## 6. スコープ外

- 承認フロー、複数ユーザー、認証（ただしユーザーIDの項目は持たせておく）
- 運賃の自動計算（外部の API から運賃の数値を受け取ること。U1 で、経路結果の URL を付けるところまでにした）
- 祝日を自動で休日にすること（祝日は一括設定で除き、名前を表示するだけ。休日にするのは手で行う）
- 祝日の一覧をインターネットから取ること、会社独自の休日（年末年始・創立記念日など）を一覧に入れること
- CSV出力、PDF出力（出力しやすいデータの形にだけしておく）
- スマホなど他端末からの利用、外部へのデプロイ
- 会社への提出・精算システムとの連携
- 1日に複数の通常ルートを使う、通常ルートを片道だけにする（これらは「追加の移動」で表す）
- 月をまたぐ一括設定

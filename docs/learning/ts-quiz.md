## 再開のしかた（新しいセッションの Claude へ）

1. `learn` スキル（`/learn`）を使い、**テスター兼チューターとして**進める。
2. 進め方（第1弾で効果があったやり方）:
   - 1ターンに1問。答えを見て「合っている／惜しい／違う」を具体的に返し、仕組みを短く説明してから次の問いへ
   - 答えをすぐ教えず、ヒントを出して自力で言わせる。正解を言い当てたら理由まで確認する
   - 各問に判定（◎説明できる／○おおむね／△あいまい）を付け、下の表を更新する
   - 返事は短い日本語。長い答えを求めない（ユーザーは短く答えるタイプ）

### D. データを扱う

**Q13. reduce（第12章）** `fare.ts` の `record.extraTrips.reduce((sum, trip) => sum + extraTripFare(trip), 0)` について。
(a) 第2引数の `0` は何の役目か。 (b) `0` を書かなかったとき、`extraTrips` が空の配列だと何が起きるか。

**Q14. Map（第14章）** 祝日の一覧 `HOLIDAYS` は `ReadonlyMap<DateString, string>`。
(a) `HOLIDAYS.get("2026-12-25")` の型は何で、使う側は何をしなければならないか。
(b) ふつうのオブジェクトでなく `Map` にした理由（`holidays.ts` のコメントの落とし穴）。
(c) `ReadonlyMap` にすると、何ができなくなるか。

**Q15. タプル型（第18章）** `CSV_HEADER` は `as const` 付きの13個の見出し、`CsvRow` はそこから作ったタプル型。
(a) `as const` が無いと `CSV_HEADER` の型はどうなるか。
(b) 行の要素を1つ入れ忘れて12個にしたとき、`string[]` の場合と `CsvRow`（タプル）の場合で、それぞれ気づくのはいつか。

### E. 設計

**Q16. 依存性の注入（第15章）** `backend` の `RouteSearch` インターフェースと `UnavailableRouteSearch`（キーが無いときの偽物）について。
(a) 呼び出す側がインターフェースだけを知っていると何がうれしいか。
(b) テストで駅すぱあとの本物の API を呼ばずに済ませるには（構造的型付けの知識が使える）。

### F. React

**Q17. 制御されたフォーム（第5章）** `<input value={form.name} onChange={...} />` の書き方を何と言うか。`onChange` を書かずに `value` だけ渡すと画面で何が起きるか。

**Q18. 一覧と key（第8章）** `{records.map((r) => <li key={r.date}>{r.date}</li>)}` について。
(a) `key` は何のためにあるか。 (b) `key={index}` にすると、並べ替えや削除のときに何が困るか。

**Q19. state の持ち上げ（第9章）** カレンダーの親（`CalendarPage`）が日次記録の一覧を持ち、子の `DayPanel` に渡している。子が自分で持たず親が持つ理由は何か。子が記録を変えたいとき、どうやって親に伝えるか。

**Q20. useState と型（第5・2章）** `ExtraTrips.tsx` の `useState<FormState>({ kind: "closed" })`。`FormState` が判別可能なユニオン型だと、`boolean` を2〜3個並べる書き方（`isOpen`・`isEditing` …）より何がよいか。

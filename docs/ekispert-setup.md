# 駅すぱあと API フリープランの申し込みと確認

経路検索（要件 U1・[ADR-0002](adr/0002-route-search.md)）を本物の API で試すための手順。Epic [#71](https://github.com/Mika777v/routepense/issues/71)。

申し込みとメールの送信はオーナーが行う。**キー・氏名・メールアドレスは、このリポジトリに書かない。**

## 今の状況

- 2026-11-02: まだ申し込んでいない（このファイルを用意した。E09-T1）

状況が変わったら、ここに日付と一緒に1行足す（例: 「申し込んだ」「キーが届いた」「localhost の連絡をした」「返事が来た」）。

## 1. 申し込む

1. 申し込みのページを開く: <https://api-info.ekispert.com/form/free/>
2. 利用規約を読んでからフォームを埋める。迷いそうな欄の考え方:

| 欄 | 書くこと | 理由 |
|---|---|---|
| 個人か法人か | 個人 | 個人の学習目的で、会社のシステムには組み込まない（要件「スコープ外」: 会社への提出・精算システムとの連携） |
| 利用目的 | 「個人の通勤交通費の記録アプリ（学習目的）で、登録した通勤ルートの経路結果ページの URL を付けるため」 | ADR-0002 の決定どおり。運賃の数値は取らない |
| ドメイン（利用するサイトの URL） | 外部に公開するドメインは無い。フォームが必須なら、手元で使うこと（localhost）を書けるか確かめ、書けなければ下の「2. localhost の連絡」で補う | このアプリは外部にデプロイしない（要件「スコープ外」） |

3. 送信したら、「今の状況」に申し込んだ日を書く。キーはメールで届く（ADR-0002 の調べでは3営業日ほど）

フォームの欄の名前や中身は、このファイルを書いた時点で確かめられていない（作業した環境から申し込みのページが開けなかった）。実際のフォームと違っていたら、このファイルを直す。

## 2. localhost の連絡

仕様書によると、フリープランのキーは申し込みのときのドメインに結び付き、localhost から使うと 403 になる。localhost から使うには `info@val.co.jp` への連絡が要る。キーが届いたら、次の下書きを元に送る（〈 〉の中はオーナーが埋める）。

```text
件名: 駅すぱあと API フリープラン localhost での利用について

株式会社ヴァル研究所 ご担当者様

駅すぱあと API フリープランを申し込みました〈氏名〉と申します。
〈申し込んだ日〉に申し込み、アクセスキーを受け取りました。

個人で使う通勤交通費の記録アプリ（学習目的）で、
登録した通勤ルートの経路結果ページの URL を付けるために利用します。
アプリは自分のパソコンの中だけで動かし、外部には公開しません。

そのため、localhost（http://localhost）からの利用を許可していただけますでしょうか。
呼び出す API は「経路探索（簡易）」（/v1/json/search/course/light）だけです。

どうぞよろしくお願いいたします。

〈氏名〉
〈メールアドレス〉
```

メモ: このアプリは、ブラウザからではなく backend（Node.js）から API を呼ぶ（キーをフロントに渡さないため。ADR-0002）。403 の判定が何で行われるか（送り元のドメインか、ほかの情報か）は仕様書に書かれていない。返事にその説明があれば、ここに書き足す。

## 3. キーが届いた後の確認

次の作業は Task で行う。

- [ ] `backend/.env` にキーを書き、`npm run dev` のログに「経路検索: 駅すぱあと API フリープラン」と出る（README「経路検索（駅すぱあと API）のキー」）— [#73](https://github.com/Mika777v/routepense/issues/73)
- [ ] ルートの画面の「経路を調べる（駅すぱあと）」で、経路結果のページが開く — #73
- [ ] 403 が出たら、localhost の連絡の返事を待つ（連絡がまだなら送る）— #73
- [ ] 保存した URL を 1日後・7日後に開き直して、開けるかを記録する — [#74](https://github.com/Mika777v/routepense/issues/74)

クラウドのセッションで試すときは、環境の設定でキーの環境変数（`EKISPERT_API_KEY`）を入れ、ネットワークで `api.ekispert.jp` を許可してから、新しいセッションで始める（設定はセッションを始めるときに読み込まれる）。ただし、クラウドから呼ぶと送り元が localhost ではないため、localhost の許可とは別の扱いになるかもしれない。まずは手元のパソコンで試す。

# 第8章 配列から画面を作る（map と key）

## この章で学ぶこと

1. 配列を `map` で JSX（画面の部品）の配列に変えて、一覧や表を描く方法
2. React が `key` を求める理由と、よい `key` の選び方
3. 画面に出す形（週ごとの配列）を、描く前に純粋関数で作っておく考え方

## 前提知識

- 第5章（React の制御されたフォーム）、第6章（純粋関数とテスト）
- Java の `for` 文と、`Stream#map`

| | Java（Swing・テンプレートなど） | React + TypeScript |
|---|---|---|
| 一覧を描く | `for` で1行ずつ部品を `add` する | 配列を `map` して、JSX の配列を返す |
| 行の見分け方 | 部品のオブジェクトそのもの | `key`（兄弟の中で一意な文字列か数） |
| 表の形を作る | 描きながら行や列を数える | 先に「週の配列」を作ってから描く |

## 概念の説明

### map で配列を JSX の配列に変える

**定義**: `Array#map` は、配列の要素1つずつに関数を当てて、同じ長さの新しい配列を返すメソッドです。React では、JSX（`<li>...</li>` のような画面の部品の書き方）も値なので、`map` で「データの配列」を「部品の配列」に変えられます。`{}` の中に部品の配列を置くと、React は順に並べて描きます。

```tsx
const names = ["自宅↔本社", "自宅↔客先A"];

function RouteNames() {
  return (
    <ul>
      {names.map((name) => (
        <li key={name}>{name}</li>
      ))}
    </ul>
  );
}
```

Java の `for` 文のように「描く」命令を書くのではなく、「この配列は、こういう部品の並び」と**式**で書くのが React の書き方です。

### key は「どの要素がどれか」を React に教える名札

**定義**: `key` は、`map` で作った兄弟の部品それぞれに付ける、兄弟の中で一意な名札です。

**理由**: React は、画面を描き直すとき、前の部品の並びと新しい並びを比べて、変わったところだけを直します。並びの途中に要素が入ったり消えたりしたとき、`key` が無いと「何番目か」でしか比べられず、別の要素の状態（入力中の文字など）を取り違えることがあります。`key` があれば、同じ名札どうしを同じ要素として比べられます。

よい `key` の条件:

- 兄弟の中で一意（ほかの一覧と同じ値でもよい）
- 描き直しても変わらない（`Math.random()` は毎回変わるので使えない）
- データ自身が持つ値（`id`・日付など）を使う

配列の添字（`index`）は、並びが変わらない一覧でだけ使えます。

**`key={index}` で何が起きるか**: React は `key` が同じ要素を「同じもの」と見なして、前の画面の部品（DOM）を使い回します。先頭を削除すると、残った行の `key` が 0, 1, …と振り直されるので、React は「0番の行の中身が変わった」と考えます。画面の部品は削除せず、**最後の部品が消され**、残る行には**元の1行目の部品**が付きます。

```tsx
// 買い物リスト ["パン", "牛乳", "卵"] を key={index} で描き、各行に <input defaultValue={item} /> を置く
// 3つの入力欄の画面上の文字は「パン」「牛乳」「卵」
// 先頭の「パン」を削除すると、データは ["牛乳", "卵"] になる
```

`defaultValue` は**最初に描いたときだけ**効く値です（2回目以降の描き直しでは読まれません）。使い回された入力欄には、元の文字が残ったままなので、画面は次のようになります。

| 行 | 期待する文字 | 実際の画面（`key={index}`） | 実際の画面（`key={item}`） |
|---|---|---|---|
| 1行目 | 牛乳 | **パン**（元の1行目の入力欄がそのまま残る） | 牛乳 |
| 2行目 | 卵 | **牛乳**（元の2行目の入力欄がそのまま残る） | 卵 |
| 3行目 | （無い） | （最後の入力欄が削除される） | （「パン」の行が削除される） |

行の表示（`<li>{item}</li>` のような**データから作る文字**）は正しく変わりますが、入力欄に打った文字や `defaultValue` のような**画面側が覚えている状態**は、行についていきません。`key` にデータ自身の値（`id` など）を使うと、削除される行の入力欄がそのまま消えるので、この食い違いは起きません。

### 描く前に、画面の形をデータで作る

カレンダーは「7列 × 4〜6行」の表です。描きながら「何列目か」を数えると、JSX の中に計算が混ざって読みにくく、テストもしにくくなります。そこで、先に**週ごとの配列**（`(日 | null)[][]`）を純粋関数で作り、JSX は「配列の配列を、行と列に `map` するだけ」にします。

```ts
// 1週 = 7マス。前後の月の日は null（空のマス）
type Week = (number | null)[];

const weeks: Week[] = [
  [null, null, null, null, null, null, 1],
  [2, 3, 4, 5, 6, 7, 8],
];
```

```tsx
<tbody>
  {weeks.map((week) => (
    <tr key={week.find((day) => day !== null)}>
      {week.map((day, i) => (day ? <td key={day}>{day}</td> : <td key={`empty-${i}`} />))}
    </tr>
  ))}
</tbody>
```

## このプロジェクトでの実例

### 月を週の配列に変える（`frontend/src/calendar/month.ts` の `buildCalendar`）

`buildCalendar(month, records)` は、月とその月の日次記録から、`CalendarWeek[]`（週の配列）を返す純粋関数です。

- 日付から記録をすぐ引けるよう、最初に `new Map(records.map((r) => [r.date, r]))` を作ります。`Map` は「キーと値の組」の入れ物で、Java の `HashMap` に当たります
- 記録の無い日は `{ kind: "unentered" }`、ある日は `{ kind: "recorded", record, fare }` にします（第2章の判別可能なユニオン型）。「未入力」を勤務区分に入れない決まり（要件定義 §5）を、画面の側でも型で守っています
- 月曜始まりにするため、`WEEK_ORDER = [1, 2, 3, 4, 5, 6, 0]` の中での1日の位置だけ、先頭を `null` で埋めます

計算はここで終わっているので、`month.test.ts` で「2026年11月は6週で、最初の週は6マス空く」のように、画面を使わずに確かめられます。

### 週の配列を表に描く（`frontend/src/calendar/MonthCalendar.tsx`）

`weeks.map` で `<tr>` を、`week.map` で `<td>` を作ります。

- 日のマスの `key` には日付（`day.date`）を使います。月の中で一意で、描き直しても変わりません
- 空のマスは日付を持たないので、`empty-${i}`（列の位置）を `key` にします。空のマスは状態を持たず、並びも変わらないので、位置で十分です
- 行の `key` には、その週の最初の日付を使います

### 見出しの曜日（同じファイル）

`WEEK_ORDER.map((weekday) => <th key={weekday}>...)` のように、曜日の数（0〜6）をそのまま `key` にしています。数も `key` に使えます。

## よくある間違いと、型エラーの読み方

### 1. key を付け忘れる

```tsx
{names.map((name) => <li>{name}</li>)}
```

型エラーにはなりませんが、開発中のブラウザのコンソールに `Each child in a list should have a unique "key" prop.`（一覧の子には一意な key が要る）と警告が出ます。

### 2. map の中で JSX を返し忘れる（型エラーになる例）

```tsx
// {} で囲むと「関数の本体」になり、return を書かないと undefined を返す
{names.map((name) => { <li key={name}>{name}</li>; })}
```

`map` の結果は `void[]` になり、画面には何も出ません。lint（ESLint）で「式の値を使っていない」と指摘されることもあります。`=> (...)` と丸かっこにするか、`return` を書きます。

### 3. 配列の要素を `[]` で取り出すと undefined かもしれない（型エラーになる例）

このプロジェクトの tsconfig では `noUncheckedIndexedAccess` が有効なので、`weeks[0]` の型は `CalendarWeek | undefined` です。

```ts
const firstDay = weeks[0][6];
// error TS18048: 'weeks[0]' is possibly 'undefined'.
```

「`weeks[0]` は undefined かもしれない」という意味です。`weeks[0]?.[6]` のように `?.`（undefined なら先を読まずに undefined を返す）を使うか、`if` で確かめてから使います。

## 練習問題

1. 次の一覧で、`key` に `index` を使うと困るのはどんなときですか。
   ```tsx
   {routes.map((route, index) => <RouteTicket key={index} route={route} />)}
   ```
2. `buildCalendar("2026-02", [])` は何週になりますか。2026-02-01 は日曜です。
3. `days`（`CalendarDay[]`）から、出勤の日の日付だけの配列を作る式を、`filter` と `map` で書いてください。

## 理解の確認

カレンダーの「何列目に置くか」の計算を、JSX の中ではなく `buildCalendar` に置いたのはなぜですか。「テスト」という言葉を使って、一言で説明してみてください。

## 解答

1. ルートを削除したり、並びが変わったりしたときです。たとえば先頭のルートを消すと、2番目のルートが `key={0}` になり、React は「0番の切符の中身が変わった」と見なします。選択中の表示や入力中の値が、別のルートに付いてしまうことがあります。`route.id` を使えば起きません。
2. 5週です。1日が日曜なので最初の週は6マス空き、1日だけが入ります。残りの27日で、3週（21日）と6日になるので、1 + 3 + 1 = 5週です。
3. 例:
   ```ts
   days
     .filter((day) => day.status.kind === "recorded" && day.status.record.workStyle.kind === "commute")
     .map((day) => day.date);
   ```
